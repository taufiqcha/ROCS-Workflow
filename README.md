# Clustering-seeded rank-opposition crow search for cloud workflows

Code for *A clustering-seeded rank-opposition crow search algorithm for cloud workflow scheduling*.

`code/rocs.py` holds the proposed method, namely rank-opposition jumping of Eq. (7) and ROCS of
Algorithm 1. `code/dcsa.py` holds the dual-encoded crow search DCSA of Algorithm 2, its key-based
decoder, and the dual-encoded GA. `code/model.py` holds the workflow model of Section 2, the
list-scheduling decoder of Eq. (3), HEFT, PEFT, and the choice of the shared priority order.
`code/clustering.py` is the edge-zeroing heuristic, `code/baselines.py` holds CSA, CSA-OBL, PSO, GA,
and PCSA, `code/independent.py` holds the independent-task model with LPT and Min-Min, and
`code/exact.py` is the CP-SAT model of Eqs. (9) to (11). `code/selection_rule.py` builds the selection
rule of Section 3.5.

The scripts `run_workflows.py`, `run_e4.py`, `run_e5.py`, and `run_e7.py` run the experiments of
Table 2. `analysis.py` recomputes every value of Section 5 from `results/` and writes
`results/summary.md`. `figures.py` draws Figures 2 to 6, and `validate.py` runs the checks of
Section 4.2. `results/` holds the raw makespans and run times of every run.

## Data

The workflows are generated by the [WfCommons](https://github.com/wfcommons/wfcommons) 1.5 recipes,
which are derived from real execution traces, so no data has to be downloaded. The simple and
stratified independent-task sets are generated in `code/independent.py`.

## Run

Python 3.11.

```bash
pip install -r requirements.txt
cd code
python3 validate.py
python3 analysis.py
python3 figures.py
python3 run_workflows.py --out ../results/e1.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles --sizes 500 --ccr 1,5 --seeds 10 --budget 100 --out ../results/e2_100n.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles --sizes 500 --ccr 1,5 --seeds 10 --budget 500 --out ../results/e2_500n.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --vms 8 --out ../results/e3_8vm.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --vms 32 --out ../results/e3_32vm.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --speeds 450,500,550 --out ../results/e3_low_heterogeneity.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --speeds 250,500,1000 --out ../results/e3_high_heterogeneity.csv
python3 run_e4.py
PYTHONHASHSEED=0 python3 run_e5.py
python3 selection_rule.py
python3 run_e7.py
```

`analysis.py` and `figures.py` need only `results/`. Every metaheuristic draws from a generator seeded
with the instance seed, so a rerun reproduces the archived makespans exactly, and only the run times
and the CP-SAT columns depend on the machine. WfCommons orders the tasks of the Rnaseq recipe
through a Python set, which is why `run_e5.py` requires `PYTHONHASHSEED=0`. The scripts use seven
worker processes by default, which `--workers` changes.
