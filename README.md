# Clustering-seeded rank-opposition crow search for cloud workflows

Code and results for *A Clustering-Seeded Rank-Opposition Crow Search Algorithm for Cloud Workflow Scheduling*.
Release v1.1 is the version tied to the revised manuscript.

## Code

| File | Content |
|---|---|
| `code/rocs.py` | Rank-opposition jumping and ROCS, the proposed refinement |
| `code/dcsa.py` | Dual-encoded crow search (DCSA), its key-based decoder, and the dual-encoded GA |
| `code/model.py` | Workflow model, insertion-based list-scheduling decoder, HEFT, PEFT, and the shared priority order |
| `code/clustering.py` | Edge-zeroing (EZ) clustering |
| `code/baselines.py` | CSA, CSA-OBL, PSO, GA, and PCSA |
| `code/independent.py` | Independent-task model with LPT and Min-Min |
| `code/exact.py` | CP-SAT reference model |
| `code/selection_rule.py` | Instance features and the decision tree that decides when to refine |
| `code/run_workflows.py`, `run_e4.py`, `run_e5.py`, `run_e7.py` | Experiments E1 to E7 |
| `code/analysis.py`, `code/figures.py` | All reported values (`results/summary.md`) and the result figures |
| `code/validate.py` | HEFT example of Topcuoglu et al. (2002) and decoder consistency |
| `revision/` | Experiments and analyses added in the revision, listed below |

## Instances and settings

The workflows are generated by the [WfCommons](https://github.com/wfcommons/wfcommons) 1.5 recipes, so no
data has to be downloaded. An instance is identified by the recipe name, the requested size, the CCR, and
the seed. Workflow instances use seed 1000 + s for the benchmark and 2000 + s for the small CP-SAT
instances, and the Rnaseq run times use seed 3000 + s. The Rnaseq recipe generates no dependency edges.
Fleets have 16 VMs at 400, 500, and 600 MIPS unless a script states otherwise. The comparator settings are
in the docstrings and argument defaults, and the tuning used seeds 0 to 9, disjoint from the evaluation
seeds.

## Run

Python 3.11, tested on an Apple M1 with macOS 27.2.

```bash
pip install -r requirements.txt
cd code
python3 validate.py
python3 analysis.py
python3 figures.py
python3 run_workflows.py --out ../results/e1.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles --sizes 500 --ccr 1,5 --seeds 10 --budget 100 --out ../results/e2_100n.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles --sizes 500 --ccr 1,5 --seeds 10 --budget 500 --out ../results/e2_500n.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --vms 8 --out ../results/e3_8vm.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --vms 32 --out ../results/e3_32vm.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --speeds 450,500,550 --out ../results/e3_low_heterogeneity.csv
python3 run_workflows.py --recipes Epigenomics,Montage,Genome,Cycles,Seismology --sizes 500 --ccr 1,5 --seeds 10 --speeds 250,500,1000 --out ../results/e3_high_heterogeneity.csv
python3 run_e4.py
PYTHONHASHSEED=0 python3 run_e5.py
python3 selection_rule.py
python3 run_e7.py
cd ..
PYTHONHASHSEED=0 python3 revision/independent_bounds.py
PYTHONHASHSEED=0 python3 revision/lp_rounding.py
python3 revision/jump_ablation.py
python3 revision/comparators.py
python3 revision/budget_curves.py
python3 revision/cpsat_continuous.py
python3 revision/equal_time.py --workers 4
python3 revision/family_stats.py
python3 revision/selection_policy.py
python3 revision/end_to_end_cost.py
```

`analysis.py`, `figures.py`, `family_stats.py`, and `selection_policy.py` need only `results/`. Every
metaheuristic draws from a generator seeded with the instance seed, so a rerun reproduces the archived
makespans exactly, and only the run times and the CP-SAT results depend on the machine. WfCommons orders
the tasks of the Rnaseq recipe through a Python set, which is why the Rnaseq scripts require
`PYTHONHASHSEED=0`. The scripts use seven worker processes by default, which `--workers` changes, and
`cpsat_continuous.py` and `equal_time.py` should run alone because they measure time.
